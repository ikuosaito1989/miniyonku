# レース描画の計測メモ

2026-11-13、390×700 CSS pxのヘッドレスChromium（ソフトウェアWebGL）、天頂決戦・同じ5台の全体表示で比較した。実機iPhoneのFPS・GPU時間ではない。

描画用のコース区間は、こもれび720→381、天頂4800→2590、蒼天4800→2564。走行サンプルは変更していない。ジャンプの開口・路面／レール色の変わり目は残し、曲率や姿勢変化が大きい箇所は元の密度を維持する。生成した描画用サンプルは同じコースの再挑戦時に再利用する。

車体は同じ車輪のスポークだけをインスタンス化し、車輪ごとの回転階層を維持する。設定画面のモデルは従来どおり。車体の他の静的部品、実機でのフレーム時間・GC・端末別GPU負荷、ロードの分割と資源解放の実測は引き続き必要。

## レース準備とモバイル解像度

準備を環境マップ・会場・コース・各車体に分け、区切りごとに入力・描画へ制御を返す。読み込み表示は最初の描画まで維持する。`?renderstats` で各段階と最初の描画の所要時間をブラウザのコンソールに出力する。初期化中の終了では部分的に作った資源も破棄する。

390×600 CSS px・DPR2のヘッドレスChromium／ソフトウェアWebGLによるこもれびの一例は、環境96ms・会場42ms・コース72ms・車体合計149ms・初回描画854ms。処理間に11回タイマーが実行され、中断後はキャンバスと結果通知が残らなかった。初回描画は依然として重く、時間は端末やGPUによって異なる。

モバイルの上限は長辺1600→1440px、総画素144万→115.2万に変更。例として844×300 CSS px・DPR2では1600×569→1440×512で約19%画素が減る。390×524 CSS px・DPR2の780×1048は変わらない。ソフトウェアWebGLで同じ場面を3フレームずつ測ると旧5.2ms/フレーム、新10.6ms/フレームで、短い計測のばらつきもあり速度改善は確認できていない。実機iPhoneの画質・GPU時間、長時間走行、材質・影を個別に切り分けた比較は未実施。
